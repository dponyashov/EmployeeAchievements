Привет! Мы продолжаем разработку проекта "1С:ERP Управление предприятием" на Vite + React + RTK Query + Axios + TS. 
Вот текущий статус и стек, который мы полностью реализовали и настроили:
1. Авторизация: JWT (Access Token в Redux, Refresh Token в HttpOnly Cookies). Кастомный baseQuery (Axios) автоматически делает тихий /auth/refresh при 401 ошибках и при жестком обновлении страницы (F5). Для этого внедрена стадия инициализации сессии isInitializing в App.tsx.
2. Роутинг: React Router v6 (createBrowserRouter / RouterProvider). Пути абсолютные. Защищены через ProtectedRoute и RoleGuard (проверка массива ролей user.roles: ROLE_ADMIN, ROLE_USER, ROLE_REPORT).
3. Интерфейс: Стиль 1С:Такси (желто-серая гамма). Двухколоночный макет (ErpHeader, ErpFooter, боковая ErpSidebarMenu, Outlet для контента). Рабочий стол (/dashboard) — сетка плиток 4х3 высотой 180px.
4. Вынесенные UI компоненты: ErpCommandBar (для списков/таблиц с кнопками Создать, Изменить, Удалить, Обновить и полем поиска внизу) и ErpFormButtons (сохранение форм через type="submit").
5. Подсистема НСИ (Справочники): Управляется метаданными с сервера по адресу /directory. Реализован DirectoryDispatcher и DirectoryItemDispatcher с PATCH-обновлением, динамическими тегами кэша и централизованным ErpErrorBoundary баннером ошибок 400 Bad Request ({message: []}).
6. Реализованные справочники: 
   - /position (Должности) — Список, Форма.
   - /department (Отдели) — Список, Форма (с useEffect для PATCH).
   - /service (Услуги) — Список (с тарифами), Форма.
   - /component (Компоненты услуг) — Список, Форма.
   - /profile (Сотрудники) — Двухпанельный журнал (слева таблица с колонкой Email и поиском по фамилии, справа анкета просмотра или форма редактирования с динамическими select должностей и отделов).
7. Плитка Справочников: отображает 3 видимых справочника шрифтом 14px (height: 70px) и остальные по скроллу. Плитка сотрудников выводит живой счетчик "В штате: X".
8. Админка (/admin): Изолированные компоненты (список, сброс пароля, матрица ролей). Ленивый дозапрос ролей по GET auth/user/{id}/roles, если прилетел null. Изменения прав идут без инвалидации — через ручное точечное обновление кэша (onQueryStarted), чтобы чекбоксы не слетали.
9. Задачи (/tasks): Двухпанельный журнал. Для ROLE_SUPERVISOR выводится список сотрудников отдела, который скрывается при переходе в форму CRUD. Связанная табличная часть «Запросы к задаче» (POST /task/{id}/query и DELETE) обновляется на лету через точечный .find() в актуальном кэше. Добавлена колонка «За период» (year.month). Счетчик на плитке живой и суммирует задачи подчиненных.
10. Отчеты (/reports): GET /report с query-параметрами (years, months, serviceIds, componentIds через запятую), кастомный сериализатор, постраничная пагинация и фильтр Строк на странице (size).
11. Общие UI: ErpCombobox (с поиском и ▼), ErpErrorBanner (с глубоким рекурсивным поиском массива message для отлова 400 ошибок), ErpHeader (кнопка Рабочего стола в стиле Выход).
12. Рабочий стол: Сетка 4х3 (высота 180px). display: 'contents' на обертках плиток для сохранения верстки и кликабельности. Плитки и меню жестко синхронизированы с allowedRoles из menuConfig.
Всё скомпилировано и стабильно работает. Нам осталось реализовать подсистемы: "Мои задачи" (/tasks), "Отчеты и анализ" (/reports) и "Администрирование" (/admin).
